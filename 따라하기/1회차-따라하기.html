6. state — 화면이 움직이기 시작한다

20:20 · 20분카드를 클릭하면 뜻이 보이게

props 는 밖에서 넣는 값, state 는 안에서 변하는 값입니다.

src/components/WordCard.jsx
import { useState } from 'react'

export default function WordCard({ word, phonetic, partOfSpeech, meaning, example }) {
  const [revealed, setRevealed] = useState(false)
  //     지금 값        바꾸는 함수          처음 값

  return (
    <article className="card" onClick={() => setRevealed(!revealed)}>
      <div className="card-head">
        <h2 className="card-word">{word}</h2>
        <span className="card-pron">{phonetic}</span>
      </div>
      <span className="card-pos">{partOfSpeech}</span>

      {revealed ? (
        <>
          <p className="card-meaning">{meaning}</p>
          <p className="card-example">{example}</p>
        </>
      ) : (
        <p className="card-hint">클릭해서 뜻 보기</p>
      )}
    </article>
  )
}
반드시 지킬 것

revealed = true 처럼 직접 대입하면 화면이 안 바뀝니다. 반드시 setRevealed(...) 를 통해서 바꿉니다.

확인해보세요

카드를 하나만 클릭하면 그 카드만 뒤집힙니다. 카드마다 각자의 revealed 를 갖고 있기 때문입니다.

자주 나는 에러

Too many re-renders

원인: onClick 에 함수 호출 결과를 넘겼습니다. 렌더하는 순간 바로 실행되고, 실행되면 다시 렌더되고, 무한 반복됩니다.

고치는 법
<button onClick={setRevealed(true)}>        ← 즉시 실행됨
<button onClick={() => setRevealed(true)}>  ← 클릭 시 실행할 함수
화면이 안 바뀝니다

setRevealed 를 쓰지 않고 변수에 직접 대입했을 가능성이 큽니다. React는 set 함수를 통해서만 변화를 알아챕니다.

Objects are not valid as a React child

객체를 그대로 화면에 그리려고 한 것입니다. {item} 이 아니라 {item.word} 처럼 안의 값을 꺼내야 합니다.

7. 조건부 렌더링과 0의 함정

20:40 · 15분세 가지 방법

패턴
// 1. 삼항 — 둘 중 하나를 그린다
{revealed ? <p>{meaning}</p> : <p>클릭해서 뜻 보기</p>}

// 2. && — 조건이 참일 때만 그린다
{example && <p>{example}</p>}

// 3. 함정 — 개수가 0이면?
{words.length && <WordList />}      ← 화면에 "0" 이 찍힙니다
{words.length > 0 && <WordList />}   ← 이렇게 고칩니다
왜 0이 찍히나

0 && X 의 결과는 0 입니다. 그리고 React는 숫자 0을 화면에 그립니다. (false, null, undefined 는 안 그립니다)

8. 목록을 state로 — 삭제 버튼

20:55 · 15분지울 수 있게 만들기

src/App.jsx
import { useState } from 'react'
import WordList from './components/WordList.jsx'
import { WORDS } from './data/words.js'

export default function App() {
  // 목록을 지울 수 있으려면 "변하는 값" = state 여야 합니다
  const [words, setWords] = useState(WORDS)

  function handleDelete(id) {
    // 원본을 고치지 않고, 새 배열을 만듭니다
    setWords(words.filter((item) => item.id !== id))
  }

  return (
    <>
      <header className="page-header">
        <h1 className="page-title">나만의 단어장</h1>
        {/* WORDS.length 가 아니라 words.length — 지운 결과가 반영돼야 하니까요 */}
        <p className="page-subtitle">오늘 외울 단어 {words.length}개</p>
      </header>

      {words.length === 0 ? (
        // words.length && … 로 쓰면 화면에 0 이 찍힙니다 — §7의 그 함정
        <p className="empty-message">단어를 모두 지웠습니다. 새로고침하면 돌아옵니다.</p>
      ) : (
        <WordList words={words} onDelete={handleDelete} />
      )}
    </>
  )
}

9. 심화 — 이 화면은 어떻게 만들어졌나

여기부터는 손을 쉬셔도 됩니다

오늘의 결과물은 이미 여러분 노트북에 있습니다. 지금부터는 방금 만든 게 대체 어떻게 화면이 된 건가를 들여다봅니다. 처음이시면 “아 그렇구나” 정도로 들으셔도 충분합니다. 3주차·4주차에 이 얘기가 전부 다시 나옵니다.

브라우저가 화면을 만드는 순서

서버가 보낸 글자 뭉치 → 화면
서버가 보낸 것: 그냥 글자 뭉치 (텍스트)
      ▼
① 파싱          글자를 읽어서 "구조"로 이해한다
      ▼
② DOM 트리 + CSSOM 트리
      ▼
③ 렌더 트리     화면에 실제로 보이는 것만 합친다
      ▼
④ 레이아웃      어디에, 몇 픽셀로 놓일지 계산   ← 비쌉니다
      ▼
⑤ 페인트  →  ⑥ 합성      색·글자를 픽셀로 칠하고 겹친다
핵심

JavaScript가 DOM을 건드리면 ③~⑥이 다시 일어납니다. 크기·위치를 바꾸면 ④부터(비쌈), 색만 바꾸면 ⑤부터(쌈). 그래서 DOM을 자주 조금씩 건드리는 것이 웹에서 가장 비싼 일 중 하나입니다.

직접 해보기 — HTML 파일 ≠ DOM

  1. F12 → Elements 탭을 엽니다
  2. 카드의 글자를 더블클릭해서 바꿔 보세요 → 화면이 바뀝니다
  3. 새로고침 해보세요 → 바꾼 게 사라집니다
그래서

HTML은 처음 한 번 DOM을 만드는 재료일 뿐입니다. 그 뒤로 화면을 결정하는 건 지금 이 순간의 DOM이고, 그걸 바꾸는 게 JavaScript입니다.

오늘의 결론 — 화면 = f(상태)

바닐라 JSReact
상태가 어디화면(DOM) 안에 흩어져 있다. style.display 를 읽어봐야 안다변수 하나. 화면을 안 봐도 안다
무엇을 쓰나“어떻게 바꿀지”“무엇이 보여야 하는지”
상태가 늘면조합이 폭발한다변수 하나 더 추가하면 끝
📸 이 문장을 기억하세요

화면 = f(상태)

상태를 바꾸면 화면이 따라온다. 나는 화면을 직접 고치지 않는다.

CSR의 정체 — 오늘의 가장 중요한 복선

브라우저에서 우클릭 → 페이지 소스 보기 (Ctrl/Cmd + U)를 눌러보세요.

페이지 소스 — 서버가 실제로 보낸 것
<!doctype html>
<html lang="ko">
  <head> ... </head>
  <body>
    <div id="root"></div>          ← 이게 전부입니다
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>
단어가 한 글자도 없습니다
